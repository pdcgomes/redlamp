# The library's complete pass for 0.3.0: plan (2026-10-10)

The library has been on `main` since 10 October (DEC-60). This round builds what 0.3.0 still needs of it, as the owner chose (DEC-61): the accepted rows' remaining features, the shortcut editor (LIB-36), the judging tools (LIB-38) and Lightroom Classic catalogs (LIB-29), soft frames on test photos (LIB-42), then the polish phase (LIB-45). Performance (the budgets not yet met) and better testing follow the pass. A second window (LIB-20), other apps' libraries (LIB-30) and several Macs on one library (LIB-37) are for 0.3.x releases after 0.3.0.

The tracker stays the source of truth for each row; this plan is how the round is run. The library board (the workstream canvas `ws-library-catalog`) follows it as it goes.

## How the round runs

- At most three agents at a time, each in its own worktree and branch, started from `origin/main`, writing only in the paths it owns (below). Everything else is read-only for it, as `AGENTS.md` says: the tracker, the README, the Lightroom comparison, this plan, `Project.swift`, `Workspace.swift` and CI among them. It asks for changes there in its report.
- An agent commits to its own branch and never pushes, merges or rebases onto `main`. When it's done, the orchestrator rebases the branch onto `origin/main`, runs the agent's suites, `RedlampAutomationTests`, the harness build and the smoke tier (`mise run e2e`), and pushes through the push gate, one branch at a time.
- After each landing the orchestrator brings the tracker rows, their issues, the README roadmap and the comparison into step, and the next agent in the queue starts.
- Each feature lands with its regression scenario, worked through the user's own input path. Tests make their photos in `LibrarySandbox.scratch`, never in the fixtures; the Trash is the real one.
- The index schema moves only in the lens package (version 12) and then the soft frames package (13); the sidecar format only in the culling package (custom labels' colours), additively.
