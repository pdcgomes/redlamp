# INF-11: ComfyUI as a route, cloud masking and cloud denoise

**Date:** 7 October 2026. **For:** INF-11, the cloud processing study behind DEC-39, and RM-17, ComfyUI as a fill server. **Related:** RM-10 (Generative Remove on the Mac, [design](../../plans/2026-10-05-generative-fill-design.md)), DN-06 to DN-08 and the [DN-11 note](DN-11-lightroom-raw-denoise.md) (raw denoise), and the [RapidRAW study](../rapidraw-findings.md) §3.3, §3.4 and §5.2.

**How this was done.** ComfyUI's server was read from a shallow clone of [Comfy-Org/ComfyUI](https://github.com/Comfy-Org/ComfyUI) at `master` [`c9d8a6e`](https://github.com/Comfy-Org/ComfyUI/tree/c9d8a6e69c4b5ab7fa0f789e7b988c172cd31fc9) (7 October 2026; the latest release is v0.39.0 of 5 October), and its behaviour from docs.comfy.org. ComfyUI is GPL-3.0: its source was read to describe its API, and nothing was copied. Providers were read from their own documentation, pricing pages and terms; licences from GitHub's licence API, Hugging Face's model API (`cardData.license`) and the model cards. Nothing was run: no ComfyUI was installed, no account was opened, no key was used and no paid or authenticated call was made. Prices are as published on 7 October 2026, in US dollars unless stated. What couldn't be checked is marked **UNVERIFIED**, and collected in [section 4](#4-not-verified).

**Licence verdicts in this note.** On the ComfyUI path Redlamp ships workflow templates, not weights: the photographer's server downloads the weights. So a verdict says what a template Redlamp ships may name:

- **Template:** the weights allow commercial use, nothing has to flow down to Redlamp's users, and the model isn't trained on Places2 (DEC-24). Undisclosed training data is allowed, as for the on-device model (DEC-23).
- **Own workflow only:** non-commercial, flow-down (OpenRAIL), territorial or Places2-trained weights. A photographer may import such a workflow and accept its licence; Redlamp never names these models.

## Summary

- **ComfyUI's own API covers everything Generative Remove needs.** Upload the crop, mask and reference (`POST /upload/image`), queue an API-format workflow with an ID Redlamp chooses (`POST /prompt`), follow its progress (`/ws`), fetch the result (`/history/{id}`, `/view`) and cancel it (`POST /api/jobs/{id}/cancel`). Since v0.21.0 (11 May 2026) Load Image keeps a 16-bit PNG's precision, and since v0.23.0 (1 June 2026) Save Image (Advanced) writes 16-bit PNG and float EXR, so a fill no longer has to make the 8-bit round trip the RapidRAW study assumed.
- **A self-run ComfyUI has no authentication.** It binds to 127.0.0.1 by default; with `--listen`, every route is open to anyone who can reach the port. It can serve TLS, but has no users or keys, and its documentation says to go beyond loopback only on a trusted network or behind an authenticating reverse proxy. Four high-severity advisories of 15 July 2026, fixed in v0.28.0, include path traversal through the unauthenticated `POST /prompt`.
- **Hosted ComfyUI:** of the services checked, Comfy Cloud is the one a photographer can use with a subscription (from $20 a month) and an API key alone. It runs API-format workflows on RTX PRO 6000 GPUs with models already installed (whether FLUX.2 [klein] is among them wasn't verified), through the same routes as a local ComfyUI (the deprecated v1 API) or the new v2 API. Its terms rule out training on what's sent, but its retention page keeps it "for as long as necessary to operate, analyze, and improve the service". RunComfy, ComfyDeploy, ViewComfy, Comfy's own API deployments, RunPod, Modal and fal all need a deployment built first, which is a developer's task. Replicate's any-workflow model needs only a key, but its model list stops at November 2025, before FLUX.2 [klein].
- **Removal workflows with commercially licensed weights run on ComfyUI's core nodes alone:** FLUX.2 [klein] 4B with a latent noise mask and a reference latent; Qwen-Image with InstantX's inpainting ControlNet and a 4-step Lightning LoRA (ComfyUI's own template); Qwen-Image-Edit-2511; Z-Image-Turbo with Fun ControlNet Union 2.1 in its inpaint mode; and LongCat-Image-Edit, all Apache-2.0. No custom node is needed, since Redlamp crops and composites itself; the custom nodes such workflows usually use (Inpaint Crop and Stitch, comfyui-inpaint-nodes, KJNodes, Impact Pack) are GPL-3.0. Two of ComfyUI's own templates download Apache-2.0 files from repositories labelled with other licences; a Redlamp template should name the Apache-2.0 copies and pin their hashes.
- **Cloud masking adds little to Redlamp's masks.** fal (SAM 3 at $0.005 a request, SAM 3.1 at $0.01), Roboflow (SAM 3 at about $0.0015 to $0.002 an image) and Moondream host masks prompted by words, clicks or boxes; Replicate's SAM 2 is automatic only, and no SAM 3 was found there; Hugging Face's Inference Providers host no promptable segmenter. Redlamp already runs Segment Anything 2.1, SAM 3 and OWLv2 on the Mac, and a cloud mask needs the whole photo uploaded and a round trip per click. Skip it, except where a ComfyUI server already fills: SAM 3.1 runs in core ComfyUI.
- **No cloud service denoises raw data.** Topaz's API takes JPEG, PNG or TIFF ($0.08 to $0.12 for 24 MP); fal and Replicate host sRGB denoisers (NAFNet, SCUNet, SwinIR, MAXIM) and Topaz; Claid takes no raw and has no denoiser; Cloudinary, Deep-Image.ai and Autoenhance accept raws but develop them their own way. The only API that takes a raw and returns a DNG is Adobe's Photoshop API v2, with Camera Raw's classical noise-reduction sliders, for enterprise contracts only (the Lightroom API reached end of life on 31 July 2026). A 24 to 61 MP photo is 144 to 366 MB as a 16-bit TIFF, each way. Cloud denoise doesn't fit Redlamp's raw-domain, non-destructive pipeline; DN-06 to DN-08 stay on the Mac.

## 1. ComfyUI as a route

### 1.1 The API of a ComfyUI the photographer runs

ComfyUI is an aiohttp server (`server.py`). It listens on `127.0.0.1:8188` by default (`comfy/cli_args.py`). Every route below is also served under `/api/…`, so `/prompt` and `/api/prompt` are the same.

| Route | Method | What it does | Detail that matters to Redlamp |
| --- | --- | --- | --- |
| `/ws?clientId=<id>` | WebSocket | Sends the events of prompts queued with the same `client_id` | Opened before queuing. The first message is `status`, with the session ID (`sid`) the server assigned or reused |
| `/upload/image` | POST, multipart | Writes the `image` file into `input/`, or `temp/` or `output/` with `type`; optional `subfolder` and `overwrite` | Returns `{name, subfolder, type}`. A file of the same name with the same bytes is reused; otherwise the new one is renamed `name (1).png`. Requests are limited to 100 MB by default (`--max-upload-size`) |
| `/upload/mask` | POST, multipart | Copies the alpha channel of the uploaded `image` into an image already on the server, named by `original_ref` (`{filename, subfolder, type}`), and saves the result as a new PNG | Made for the browser's mask editor. Sending the mask as its own greyscale PNG, read by `LoadImageMask` with `channel: red`, is simpler |
| `/prompt` | POST, JSON | Validates `prompt` (an API-format workflow) and queues it | Optional `client_id`, `prompt_id` (a UUID the client chooses, in lowercase canonical form), `extra_data` and `front`. Returns `{prompt_id, number, node_errors}`, or HTTP 400 with `error` and `node_errors` naming the failing nodes |
| `/prompt` | GET | Number of prompts left in the queue | |
| `/queue` | GET, POST | Lists running and pending prompts. `{"delete": [ids]}` removes pending ones; `{"clear": true}` all of them | Doesn't stop a running prompt |
| `/interrupt` | POST | Stops the running prompt; with `{"prompt_id": …}` only if that prompt is the one running | With no body it stops whatever is running, whoever queued it |
| `/api/jobs`, `/api/jobs/{id}` | GET | Jobs and their state: `pending`, `in_progress`, `completed`, `failed` | Since December 2025 ([#11054](https://github.com/Comfy-Org/ComfyUI/pull/11054)) |
| `/api/jobs/{id}/cancel`, `/api/jobs/cancel` | POST | Stops a running job or removes a pending one; idempotent, returns `{"cancelled": true or false}` | Since v0.26.0, 23 June 2026 ([#14493](https://github.com/Comfy-Org/ComfyUI/pull/14493)) |
| `/history`, `/history/{id}` | GET, POST | A finished prompt's workflow, status, and each output node's files as `{filename, subfolder, type}` | Kept in memory, at most 10,000 entries (`execution.py`). POST `{"delete": [ids]}` deletes entries, not files |
| `/view` | GET | Returns a file from `output/`, `input/` or `temp/`, by `filename`, `subfolder` and `type` | Unchanged unless `preview=webp;90` or `channel=rgb` (or `a`) asks for a re-encode, so a 16-bit PNG comes back 16-bit |
| `/object_info`, `/object_info/{class}`, `/models/{folder}` | GET | Each node's inputs and outputs, including the model files a loader offers; the files in a model folder | What a template can be checked against when it's imported |
| `/system_stats`, `/features` | GET | ComfyUI, Python and PyTorch versions, devices and their free memory; server feature flags | Lets Redlamp require a minimum version |
| `/free` | POST | `{"unload_models": true, "free_memory": true}` | For `GenerativeFiller.unload()` |

Sources: `server.py` and `execution.py` at `c9d8a6e`; [Server Routes](https://docs.comfy.org/development/comfyui-server/comms_routes); the repository's `openapi.yaml`, which also describes Comfy Cloud's responses (401, 402).

**A fill, as Redlamp would make it** (from the code above and the repository's `script_examples/`; not run):

1. Encode the crop and the reference as 16-bit PNGs and the mask as an 8-bit greyscale PNG, and upload each with `POST /upload/image`.
2. Open `/ws?clientId=<id>`.
3. Fill the template's named inputs (the three file names, the seed, the prompt's text), choose a UUID, and `POST /prompt` with `{prompt, client_id, prompt_id}`.
4. Report the sampler's `progress` events (`value` of `max` steps) as 0…1. Finish on `execution_success`, or `executing` with `node: null`; fail on `execution_error` with its message; treat `execution_interrupted` as cancelled.
5. `GET /history/{prompt_id}`, take the save node's file, and `GET /view` it.
6. To cancel, `POST /api/jobs/{prompt_id}/cancel`; on servers older than v0.26.0, `POST /interrupt` with the `prompt_id` and `POST /queue` with `{"delete": [prompt_id]}`. Because Redlamp chose the ID, it can cancel a prompt whose `POST /prompt` hasn't answered yet.

**WebSocket messages.** Text frames are JSON `{"type", "data"}`: `status` (queue length), `execution_start`, `execution_cached` (nodes skipped because their results are cached; a repeat with the same seed returns at once), `executing` (the node about to run; `null` when the prompt is done), `progress` (`value`, `max`, `node`, `prompt_id`), `progress_state` (every running node's progress), `executed` (a node's UI output, such as the images it saved), `execution_success`, `execution_error` and `execution_interrupted` ([Server Messages](https://docs.comfy.org/development/comfyui-server/comms_messages), `execution.py`, `main.py`). Binary frames start with a 4-byte big-endian type (`protocol.py`): 1 is a preview image, followed by 4 bytes for its format (1 JPEG, 2 PNG); 3 is progress text; 4 is a preview with JSON metadata. A client may first send `{"type": "feature_flags", …}`, and the server answers with its own. Previews are off unless the server is started with `--preview-method`. The example node `SaveImageWebsocket` (`custom_nodes/websocket_image_save.py`) sends a full-size result as an 8-bit PNG frame, so a 16-bit result has to go through `/view`.

**Images and bit depth.**

- Since v0.21.0, Load Image decodes through PyAV ([#13594](https://github.com/Comfy-Org/ComfyUI/pull/13594): "This should fix the extra precision in high bit depth images (like 16 bit PNG) being discarded"). 8-bit formats are divided by 255; others are decoded to 32-bit floats (`comfy_api/latest/_input_impl/video_types.py`).
- Save Image writes 8-bit PNG. Save Image (Advanced), in core since v0.23.0 ([#13850](https://github.com/Comfy-Org/ComfyUI/pull/13850)), writes PNG at 8 or 16 bits and EXR at 32-bit float; later versions add AVIF (August 2026) and 16-bit float EXR (October 2026) (`comfy_extras/nodes_images.py` at v0.23.0 and at `c9d8a6e`). It saves into `output/`.
- Load Image's mask output is 1 minus the image's alpha; Load Image Mask can return a colour channel as the mask instead (`nodes.py`).
- With a latent noise mask (`SetLatentNoiseMask`), ComfyUI's sampler blends at every step: the model's prediction inside the mask, and the original latent, noised to that step's level, outside it (`KSamplerX0Inpaint` in `comfy/samplers.py`). That is what diffusers' `Flux2KleinInpaintPipeline` does, which Redlamp's MLX port follows ([design](../../plans/2026-10-05-generative-fill-design.md)).

So a crop can go up as 16-bit and come back as 16-bit with core nodes only. The RapidRAW study's open question ("ComfyUI's images are 8-bit, so a fill's round trip is too", §5.2) no longer holds for ComfyUI v0.23.0 and later. Not tested end to end.

**Beyond localhost: authentication and TLS.**

- **No authentication.** Every route is open to whoever reaches the port. The self-hosting guide: "The ComfyUI server has no authentication by default. Only bind to a non-loopback address on a network you trust, or put a reverse proxy with authentication in front of it" ([Self-Hosting Options](https://docs.comfy.org/development/deploy/self-hosting)). `--listen` with no address binds `0.0.0.0` and `::`. `--multi-user` separates users' files by a `comfy-user` header, which identifies a user but doesn't authenticate one (`app/user_manager.py`). Community add-ons exist, such as [ComfyUI-Login](https://github.com/liusida/ComfyUI-Login) (MIT), a password page.
- **A check against browsers, not clients.** Unless `--enable-cors-header` is set, the server refuses requests marked `Sec-Fetch-Site: cross-site`, and, when its host is a loopback address, requests whose `Origin` names another host, so a web page can't queue workflows on a local ComfyUI (`create_origin_only_middleware` in `server.py`). A native app sends no `Origin` and isn't affected. `--enable-cors-header` replaces the check with CORS headers allowing the given origin, or any.
- **TLS, without client certificates.** `--tls-keyfile` and `--tls-certfile` serve HTTPS and WSS on the same port; the server's TLS context doesn't ask clients for certificates (`verify_mode=CERT_NONE`). A self-signed certificate means Redlamp would pin it.
- **Its security record.** On 15 July 2026 ComfyUI published four high-severity advisories, all fixed in v0.28.0: path traversal through the unauthenticated `POST /prompt` that let a crafted workflow probe for files and read any image on the host through Load Image ([GHSA-rvxv-29p8-pxgq](https://github.com/Comfy-Org/ComfyUI/security/advisories/GHSA-rvxv-29p8-pxgq)), path traversal in model previews, and two stored cross-site scripting bugs. Custom nodes are Python that runs inside the server.
- **Files stay.** No core route deletes an uploaded input or a saved output. `temp/` is wiped when the server starts, unless the assets system is on (`main.py`, `app/assets/lifecycle.py`); with `--enable-assets`, an asset can be deleted (`DELETE /api/assets/{id}`).
- **On the Mac,** connecting to a server on the local network makes macOS 15 and later ask the photographer for local network access once ([TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)).

**Comfy API v2 and the proxy.** Comfy now offers a versioned API, v2 (beta, version 0.1.x), served by Comfy Cloud and Comfy API deployments: content-addressed assets (blake3 hashes), jobs submitted with an `Idempotency-Key`, live events over server-sent events with polling as the fallback, and cancellation ([v2 overview](https://docs.comfy.org/api-reference/v2/overview), [SDKs](https://docs.comfy.org/development/api-development/sdks)). A self-run ComfyUI speaks v2 only through [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy) (MIT) until v2 moves into ComfyUI itself. The proxy binds to loopback and refuses any other address unless it has a static bearer token (`--token`) or is told `--allow-insecure-bind`. The raw server API, by contrast, has "no compatibility guarantee across releases" ([Running Workflows](https://docs.comfy.org/development/run-workflows/overview)).

### 1.4 Assessment: ComfyUI

**Evidence:** sections 1.1 to 1.3. **Assessment:**

1. **The API fits `GenerativeFiller` as it is.** The protocol hands over an sRGB-encoded crop, mask, optional reference, seed and named prompt, reports progress, and returns the same form; each maps to an upload, a template input, the `progress` event or `/view`. Two things are missing on Redlamp's side: the protocol has no way to cancel a fill in progress, which a remote filler needs in order to send its cancel call; and a template has to carry the text of each named prompt, which the on-device model holds as embeddings. Provenance can name the server, its ComfyUI version (`/system_stats`), the template and its hash, the model files and the seed.
2. **The round trip can be 16-bit.** With core nodes on v0.23.0 or later, the crop goes up as a 16-bit PNG and comes back as one. Requiring v0.28.0 also brings July's security fixes. Measure on a real server that the round trip changes nothing outside the mask (not done here).
3. **Templates: core nodes and Apache-2.0 models only.** FLUX.2 [klein] 4B first, the model Generative Remove already uses, so a fill from a server looks like one from the Mac; then Qwen-Image's inpainting ControlNet for photographers whose servers have 48 GB. Name each file from an Apache-2.0-labelled repository and record its SHA-256 in the template. On import, check every node class and model file against `/object_info` and `/models/{folder}`, and refuse with the missing node or file named.
4. **A self-run server is for photographers who run their own network.** Accept a loopback or local-network address, or an HTTPS address; send an `Authorization` header when one is set, for a reverse proxy or comfy-api-proxy; warn against plain HTTP beyond the local network, and pin a self-signed certificate. Redlamp shouldn't suggest exposing ComfyUI on the internet: with no authentication, anyone who reaches it can run any installed node, and July's advisories show what that has allowed.
5. **Comfy Cloud is the hosted ComfyUI a photographer can set up.** A subscription and a key; Redlamp's template and its models (if installed there, UNVERIFIED); one client for both Comfy Cloud and a self-run server, since the v1 routes are the local ones with a key header. v2 is the versioned interface Comfy points new integrations at, but needs a proxy on a self-run server until it moves into core: start with the raw API for self-run servers and v1 for Comfy Cloud, and move both to v2 when ComfyUI serves it. The consent text has to say that Comfy keeps what's sent with no stated limit, though not for training; Standard runs one job at a time, so three fills from three seeds run in turn.
6. **The other hosted services suit a service Redlamp would run, not photographers.** RunComfy, ComfyDeploy, ViewComfy, Comfy API deployments, RunPod, Modal and fal each need a deployment built with models and nodes. As the back end of a Redlamp-run fill service (DEC-39's third-party route), a warm fill would cost well under a cent at their per-second rates, with cold starts as the larger cost; that route brings accounts, billing and the Mac App Store's in-app purchase rules, which are outside this note. Replicate's any-workflow model is stale for Redlamp's models.
7. **Against INF-11's other routes:** ComfyUI asks more of the photographer than a key for a model API (studied separately), since it needs a workflow and a server or a Comfy subscription; in return the photographer chooses the model, and can run it on their own GPU without a third party.

### 2.2 Assessment: cloud masking

**Assessment.** Cloud masking adds little, and costs more than it saves:

- **Redlamp already has the models on the Mac.** Vision's Subject, People and Sky; Segment Anything 2.1 (an 80 MB download) for clicks, boxes and brushes; SAM 3 (988 MB) for landscape classes and people's parts; OWLv2 for finding things by name; Depth Anything 3; and edges solved per pixel. The cloud offers the same families.
- **What it could add is small.**
  - *Free-text concepts.* Redlamp's SAM 3 ships the text features of 35 prompts and no text encoder (`packages/RedlampMasking/Resources/Models/sam3.json`), so a word it hasn't encoded can't prompt it on the Mac; fal, Roboflow and Moondream take any words. OWLv2's boxes prompting Segment Anything already find things named in words on the Mac.
  - *Larger models.* Redlamp's Segment Anything 2.1 is the tiny model, 58 ms to encode and 12 ms a prompt on the M1 Ultra (`sam2.1-tiny.json`); the cloud has Large (Replicate's SAM 2, automatic masks only). Whether Large's masks are better on photographs once Redlamp solves every edge pixel hasn't been measured, and if they are, Apple publishes Core ML conversions of SAM 2.1 small, base+ and large under Apache-2.0 ([apple/coreml-sam2.1-large](https://huggingface.co/apple/coreml-sam2.1-large)), so the answer would be a larger download, not the cloud.
- **Little memory isn't the problem it is for fills.** SAM 3 is a 988 MB download that Redlamp offers on every Mac (DEC-27), and it encodes a photo in 609 ms and answers a prompt in 86 ms on the M1 Ultra; generative fill's 4.2 to 6.6 GB peak is what small Macs lack.
- **Costs:** a mask needs the whole photo, not the crop a fill sends; hover previews and clicks need answers in milliseconds, and a cloud round trip with an upload takes seconds; and one provider's terms may license what's sent for training.

Skip cloud masking. Where a photographer has a ComfyUI server for fills, text-prompted SAM 3.1 masks come with it, through the same client, if ever wanted.

### 3.3 Assessment: cloud denoise

**Evidence:** sections 3.1 and 3.2, and Redlamp's plan: DN-07 trains a raw-to-raw denoiser for the Bayer mosaic (X-Trans in linear RGB), and DN-08 makes it a cached, non-destructive stage; the [DN-11 note](DN-11-lightroom-raw-denoise.md) found Lightroom's Denoise is one network that demosaics and denoises the mosaic on the device.

**Assessment.** Cloud denoise doesn't fit Redlamp, and nothing on offer would change that:

- **Nothing in the cloud works on raw data.** Every denoiser offered by API (Topaz, NAFNet, SCUNet, SwinIR, MAXIM, Deep-Image) works on a demosaiced, display-referred RGB image. Using one means either sending a rendered photo, which bakes in the tone and colour Redlamp's edits keep changing, or sending Redlamp's linear Rec. 2020 image, which these models aren't trained on. The services that accept raws develop them with their own demosaic and colour, so Redlamp's highlight reconstruction, demosaic, noise model and camera colour wouldn't apply.
- **Adobe's API is the one raw-in, DNG-out service, and it isn't for photographers.** It needs an enterprise contract, and its noise reduction is the classical sliders, not Lightroom's AI Denoise.
- **The data doesn't fit the edit.** A result is a whole photo, 144 to 366 MB as 16-bit RGB, which would have to be kept with the edit for it to render the same anywhere; a fill is about 6 MB at most. The upload alone takes one to two and a half minutes per photo on a 20 Mbit/s line, against a denoise on the Mac that is meant to be a background stage.
- **It wouldn't stay the same.** A provider's model can change under the same name; Redlamp's process versions keep old edits rendering as they did, which a stored result could do only by keeping every result.
- **The price is per photo, for something the Mac does free:** $0.05 to $0.32 a photo through Topaz, depending on the reseller and the size, and $0.54 to $1.37 through fal's NAFNet.

Keep DN-06 to DN-08 on the Mac. The cloud's useful role in denoise is training DN-07 on rented GPUs, which sends no photographer's photos and is already in DN-07's budget. Apple's RAW 9 (CAM-27) stays the on-device comparator.
